# Retrieval-augmented generation utilities

`chunk_text` splits characters with metadata offsets and overlap. `TitanV2Embeddings` calls Bedrock Runtime `InvokeModel` for Titan V2 (256, 512, or 1024 dimensions). Titan V2 accepts up to 50,000 characters or 8,192 tokens. The adapter enforces the character cap; exact token counting requires model-aware tokenization and is not approximated. `Retriever` accepts any object implementing `embed(text) -> list[float]`, then indexes and retrieves with cosine similarity. Equal scores retain document insertion order. The default store is in-memory and nonpersistent. Titan requests require `bedrock:InvokeModel` and may incur charges. The included RAG example shows document → chunks → vectors → search → context; it does not call a chat model.

The offline evaluation suite in `tests/evaluation/` uses four synthetic documents, three representative questions, manually fixed vectors, and macro-average Recall@K. It is a deterministic regression check for this retriever's ranking behavior, not a measure of semantic embedding quality or evidence of production retrieval performance.
