# Bedrock Converse

Create a client using `create_bedrock_runtime_client(ToolkitConfig(region_name="us-east-1"))`, then call `converse(client, model_id, prompt, system=..., temperature=..., max_tokens=...)`. The result exposes `text`, all `content_blocks`, `stop_reason`, token `usage`, and the raw response. Text blocks are concatenated for existing text callers; tool-use and other returned block types remain available. The helper sends one text user message and does not orchestrate tool calls or accept multimodal input.

Retries use botocore standard mode by default. `ToolkitConfig` also supports `connect_timeout_seconds` and `read_timeout_seconds`. Connection timeout bounds establishing a connection; read timeout bounds waiting for a response. Choose the read timeout for expected model latency and your application's request deadline; longer generation or busy models may need a larger value, while interactive applications often need a tighter bound. These settings do not change model-side generation limits.

`BedrockThrottlingError` and `BedrockAuthorizationError` are `BedrockRequestError` subclasses, with the original boto3/botocore exception preserved as `__cause__`. Messages avoid including request bodies or AWS error details. Grant `bedrock:InvokeModel` on the selected model/inference-profile resource and ensure model access is available in the account and region. Calls can incur charges. Converse request fields follow the [AWS Converse API guide](https://docs.aws.amazon.com/bedrock/latest/userguide/conversation-inference.html).
